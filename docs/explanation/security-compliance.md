# Explanation: Security & Compliance

The distribution of Department of Drug Administration (DDA) restricted substances necessitates strict regulatory compliance. The DEVI platform integrates advanced cryptographic protocols to ensure an irrefutable chain of custody during these high-risk transactions.

## The Biometric Imperative

Traditional Point-of-Sale systems rely on managerial PIN codes or password overrides for restricted transactions. These vectors are highly susceptible to credential sharing ("shoulder surfing") and social engineering, rendering the audit log unreliable.

### SimpleWebAuthn Integration
DEVI mitigates this risk by enforcing the FIDO2/WebAuthn standard via the `SimpleWebAuthn` protocol. When a Pharmacist is required to authorize a DDA sale, the system demands a cryptographic signature generated by the device's secure enclave (e.g., Apple's Secure Enclave or an Android TPM). 

This signature is unlocked exclusively via a physical biometric challenge (FaceID or TouchID). Consequently, the PostgreSQL `dda_audit_logs` record guarantees mathematically that the registered Pharmacist was physically present and actively authorized the specific dispensation.

## Hardware Identity

The DEVI architecture prohibits unauthorized edge devices from interacting with the backend API, even if a user possesses valid authentication credentials.

### Hardware-Bound JSON Web Tokens
During the kiosk provisioning phase, Zitadel issues a long-lived Service Account token. This token is bound to the physical hardware. The Go backend inspects the JWT payload and cross-references the incoming request's networking telemetry (MAC address) against the authorized `kiosks` registry within PostgreSQL.

### Rationale
This prevents a scenario where a malicious actor extracts an active user JWT and attempts to execute fraudulent transactions from an unauthorized off-site terminal. The backend mandates that all API interactions originate from physically verified and registered pharmacy hardware.
